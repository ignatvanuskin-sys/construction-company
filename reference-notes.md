# Animation reference notes

The supplied references point to six compatible interaction families rather than a single visual style. **Beam** demonstrates a moving light beam traveling around a component border; this is suitable for a restrained bronze outline on project cards and the primary CTA. **Originkit** emphasizes a library of small, composable effects such as pulsating borders, light bloom, image reveal, cursor fields, liquid grids, and glowing particles; the site should borrow the principle of one effect per component, not stack everything at once. **Transitions.dev** showcases short transitions for card resize, number pop-in, menu reveal, modal/panel reveal, image tilt, success-check morph, text reveal, shimmer, and 3D tilt; these map well to project cards, navigation, form success, and scroll entrances. **Metal** presents an animated liquid-metal shader border with options for color and glow; adapt this as a subtle warm-bronze sheen around the fixed CTA rather than a full-screen effect. **Orbs** uses small animated canvas spheres for ambient states; an understated orb cluster can live behind the process section as a quiet “thinking / forming” motif. **Canvas UI** demonstrates HTML-in-canvas/WebGL effects such as clouds, displacement, liquid, glass, particle reveal, ripple, and grid; use only a lightweight CSS/canvas ambient grain-orb field with pointer response, keeping the photography and text legible.

Implementation constraints: preserve the existing “Архитектурный кинематограф” direction, use CSS transforms/opacity where possible, gate non-essential motion behind prefers-reduced-motion, disable pointer-heavy effects on small screens, and avoid external runtime dependencies unless necessary. The desired result is a premium portfolio with three clear motion layers: (1) micro-interactions, (2) scroll reveals, and (3) one restrained ambient canvas effect.
